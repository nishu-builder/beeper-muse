# Set up Beeper Muse

You will install two pieces on the same computer: the local bridge, which creates
your dedicated Muse chat in Beeper, and the Chrome extension, which connects that
chat to your existing signed-in Muse conversation. Both must stay running.

This is an experimental community project, unaffiliated with Beeper or Meta.
It supports new text messages. It does not import chat history or handle Muse's
approvals, attachments, product cards, or later background updates.

## 1. Prepare your computer

You need macOS or Linux, a Beeper account, access to Muse at <https://muse.ai/>,
Chrome 102 or newer, Git, Node.js 24 or newer, Go 1.26 or newer, and a C compiler
for SQLite. On macOS, install the Xcode command line tools if needed.

Install [bbctl](https://github.com/beeper/bridge-manager), Beeper's official
self-hosted bridge manager. On macOS:

```sh
brew install beeper/tap/bbctl
```

Use bbctl's own instructions for Linux. Native Windows is not supported by
bbctl; WSL has not been tested with this project. Chrome and the bridge must
reach the same computer's loopback address; a remote bridge alone will not work.

## 2. Set up and start the bridge

```sh
git clone https://github.com/nishu-builder/beeper-muse.git
cd beeper-muse
npm ci --ignore-scripts
npm run build
npm start -- setup
npm start -- start
```

Follow bbctl's sign-in prompts if asked. Setup registers `sh-muse` and stores
private settings under `.local/`. Do not use this registration name if another
unrelated bridge already uses it. Never share this directory, its pairing code,
or its backups.

Leave the terminal open. Wait for the bridge to report that the Muse chat is
ready. A **Muse** conversation should appear in Beeper. This uses your Beeper
account directly; enabling the Beeper Desktop local API is not necessary.

## 3. Install the Chrome extension

Version 0.3.0 is pending Chrome Web Store review as of September 13, 2026.
Until it is approved, choose one of these:

- **Release download:** download `beeper-muse-extension.zip` from
  [GitHub Releases](https://github.com/nishu-builder/beeper-muse/releases/latest)
  and extract it to a permanent folder. In Chrome, open `chrome://extensions`,
  enable **Developer mode**, click **Load unpacked**, and select the extracted
  folder containing `manifest.json`.
- **From source:** use **Load unpacked** to select the repository's `extension`
  folder. No extension build step or generated private copy is required.

Do not load both copies. Keep the extracted folder in place; Chrome reads from
it. GitHub ZIP installations need manual updates. Once the store version is
approved, installing it through Chrome Web Store will provide automatic extension
updates. The local bridge still needs to be updated separately.

## 4. Pair with this computer

1. Pin **Beeper Muse** from Chrome's extensions menu and open its popup.
2. Open `.local/pairing-code.txt` in a text editor. Paste its 64-character code
   into the popup's **Pairing code** field.
3. Click **Pair bridge**. The bridge must be running for this check to succeed.

This code is generated by the bridge, not by Beeper or Muse. It is not an account
password. Chrome stores it locally, outside Chrome Sync, and keeps it out of
content-script storage. If the file is missing, run `npm start -- pairing-code`
from a second terminal in this repository. That preserves your current pairing.

## 5. Connect Muse and send a message

1. Open <https://muse.ai/> in Chrome and sign in to your own account.
2. Refresh the page if it was open before you installed or reloaded the extension.
3. Leave the main chat open with an empty composer. Wait for active Muse work to
   finish.
4. Open the extension and click **Connect this Muse tab**. The button changes to
   **Muse tab connected**. You only need to connect once per browser session.
5. Close the popup. In Beeper's **Muse** conversation, send
   `Reply with exactly: MUSE_CONNECTED`.

The prompt should appear in Muse, followed by a reply from the Muse contact in
Beeper. The Connect button itself does not send a test message. `0 queued` means
there is no outstanding prompt. Check [validation](validation.md) for the current
tested scope.

Keep the local bridge and Chrome running and the Muse tab open. Do not compose
manual messages in the attached tab while a bridge prompt is running. After
restarting Chrome, reconnect the tab. Use **Disconnect tab** before switching
to another tab or using Muse directly.

## Recovery

| What you see                                  | What to do                                                                                                                                    |
| --------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| Pairing fails                                 | Start the bridge, confirm it uses port 24819, and copy the code from this installation.                                                       |
| Connected, 0 queued                           | Close the popup and send a new message in Beeper's Muse chat. Connecting alone sends nothing.                                                 |
| Message queued, nothing in Muse               | Leave the Muse main chat open, clear any draft, wait for Muse to finish, and connect the tab.                                                 |
| Reload message or no response after an update | Reload the extension at `chrome://extensions`, refresh Muse, then reconnect.                                                                  |
| Message needs attention / blocked             | Follow [interrupted-job recovery](operations.md#interrupted-jobs). Check both apps before discarding a job; it may already have reached Muse. |
| Muse answered but Beeper did not              | Inspect `npm start -- status` and the bridge terminal. Do not resend blindly; see the operations guide.                                       |

Muse's product lookup or monitoring errors in its own console do not, by
themselves, establish an extension failure. Report the bridge version, queue
phase, browser version, and steps to reproduce. Redact messages, identifiers,
and secrets from logs or screenshots.

## Upgrade from version 0.2

Wait for an idle queue, stop the bridge, and back up the entire private directory.
Update the source and run `npm ci --ignore-scripts`, `npm run build`, and
`npm start -- setup`. Start the bridge again.

Remove the old unpacked extension that points at `.local/extension`. Install the
public extension from step 3, pair with `.local/pairing-code.txt`, refresh Muse,
and reconnect. Keep the private bridge databases and configuration; do not
re-register or delete your Muse chat. Version 0.3 excludes reactions from prompt
and reply text, fixing a response-capture failure seen in version 0.2.

For future updates, store installations update the extension through Chrome.
For unpacked installations, replace the extracted public files and click
**Reload** at `chrome://extensions`, then refresh Muse and reconnect. Review
release notes before updating the local bridge.
